AI Assistant

The AI Assistant is a project-aware coding agent for reading files, generating code, analyzing errors, and operating on project files.

Configuration

  1. Open a project.
  2. Open “AI Chat”.
  3. Tap the model name in the title bar and add a model.
  4. Enter an API key, API URL, and model name, then select the model.
  5. Enter a task and send it.

Set the API URL to the provider's OpenAI-compatible base URL, such as https://api.deepseek.com/v1. Requests use /chat/completions below that URL. Do not put API keys in project files or Skill files.

Task Description

Include the goal, file paths, constraints, and validation steps:

Read app/src/main/assets/activities/main/MainActivity.lua.
Fix the help-page title refresh while preserving the existing style.
Explain the changes and check related call sites.

The assistant follows a read-before-edit workflow. It can read the relevant NeLuaJ+ help documents when an API is unfamiliar.

File Operations

These operations show a confirmation dialog before execution:

  • Creating or overwriting files
  • Creating or deleting directories
  • Deleting files
  • Applying patches, replacements, and appends
  • Renaming files
  • Running Lua code

Reading files, listing directories, and searching the project do not require confirmation. Auto-approve applies only to file operations inside the current project. MCP tools and Lua execution still require confirmation.

Running Lua Code

Temporary AI code runs in a restricted sandbox, not in the current project's normal Lua environment. It can check pure Lua syntax and algorithms, but cannot access activity, Java/Android APIs, files, networking, require, or luajava. See AI Lua Sandbox for available libraries, output handling, and timeout limits.

Command Menu

The command button beside the input field provides:

  • Compress context: summarize older conversation messages while keeping recent messages.
  • Undo / redo conversation turn: change chat history without executing tools again.
  • Undo / redo file change: restore the latest Agent file transaction.
  • Switch conversation: conversations are isolated by project.
  • Settings: change API, context length, output limits, and approval options.

File undo checks the file fingerprint and refuses to overwrite externally modified content.

MCP

Add Streamable HTTP MCP servers in Settings. After connecting, the assistant discovers and calls their tools.

  • The server URL must be reachable over HTTP or HTTPS.
  • MCP tools operate on external systems and require confirmation.
  • Do not connect untrusted servers or expose API keys in server settings.
  • If a server is unavailable, disable or remove it and refresh the tool list.

Local Skills

A Skill is a local Markdown guide for a specific task. The assistant only reads SKILL.md; it does not execute Lua code from a Skill or download Skills.

Global Skills:

/sdcard/LuaJ/agents/skills/<skill-name>/SKILL.md

Project Skills:

<project>/.agents/skills/<skill-name>/SKILL.md
<project>/skills/<skill-name>/SKILL.md

A Skill may use simple frontmatter:

---
name: lua-review
description: Check Lua style and common mistakes
triggers: lua, review, check
---

Write the Skill rules and review steps here.

When a message is sent, the assistant matches Skill names, descriptions, and keywords, then adds the selected Skill body to the request. Never put secrets, private data, or unconditional dangerous actions in a Skill.

Folder Structure

Agent data is stored in /sdcard/LuaJ/agents, separately from project source files:

/sdcard/LuaJ/
├── Projects/                         Project roots (example)
│   └── MyProject/
│       ├── .agents/
│       │   └── skills/               Skills for this project
│       │       └── review/
│       │           └── SKILL.md
│       ├── skills/                   Alternative project Skill directory
│       │   └── release/
│       │       └── SKILL.md
│       ├── init.lua                  Project entry point
│       └── ...                       Project source and resources
├── agents/                           External Agent runtime data
│   ├── skills/                       Global Skills
│   │   └── lua-review/
│   │       └── SKILL.md
│   └── projects/
│       └── <project-hash>/          Data isolated per project
│           └── changesets.json       File undo/redo history
└── ...

Put project-specific rules in the project directory and shared rules in /sdcard/LuaJ/agents/skills. Use different Skill names across directories.

Data and Safety

Conversation history is stored in app data. Project-scoped Agent data is stored at:

/sdcard/LuaJ/agents/projects/<project-hash>/

File history uses changesets.json and keeps a limited number of recent records. Each project has a separate directory and file undo history. API keys are not written to the Agent project data directory.

Troubleshooting

No response after sending

Check the API key, API URL, model name, and network connection. You can use the connection test in model settings. Models without tool support are automatically requested in text-only mode.

Context compression did not change anything

Compression needs at least two separable groups of history. With very little conversation there is no older content to summarize.

File undo failed

If a file was edited after the Agent changed it, fingerprint validation prevents an overwrite. Review the current file and resolve the conflict manually.

Permission errors

The Agent needs access to the current project and its data directory. Grant NeLuaJ+ file-management permission and make sure the project path is readable and writable.
