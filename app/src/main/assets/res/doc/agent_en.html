AI Assistant

The AI Assistant is a project-aware coding agent for reading files, generating code, analyzing errors, and operating on project files.

Configuration

  1. Open a project.
  2. Open “AI Chat”.
  3. Tap the model name in the title bar and add a model.
  4. Enter an API key, API URL, model name, context window, and maximum output, then select the model.
  5. Enter a task and send it.

Set the API URL to the provider's OpenAI-compatible base URL, such as https://api.deepseek.com/v1. Models use /chat/completions by default. Enable “Use Responses API” only when the provider explicitly supports it; requests will then use /responses. Do not put API keys in project files or Skill files.

Responses API model availability, parameters, and endpoint behavior depend on the provider. Compatible relays may expose the same route without supporting official output-state replay; after switching providers or protocols, the assistant uses portable tool-call history.

Task Description

Include the goal, file paths, constraints, and validation steps:

Read app/src/main/assets/activities/main/MainActivity.lua.
Fix the help-page title refresh while preserving the existing style.
Explain the changes and check related call sites.

The assistant follows a read-before-edit workflow. It can read the relevant NeLuaJ+ help documents when an API is unfamiliar.

Closing the AI Assistant panel does not stop an active generation or tool chain; reopening it restores the current progress. Use the stop button beside the input area to terminate the task. Switching projects, creating a new conversation, or clearing the conversation cancels the active task.

File Operations

These operations show a confirmation dialog before execution:

  • Creating or overwriting files
  • Creating or deleting directories
  • Deleting files
  • Applying patches, replacements, and appends
  • Renaming files
  • Running Lua sandbox code (when “Auto-run sandbox code” is disabled)
  • Fetching public HTTPS pages or APIs (when “Auto-approve network requests” is disabled)

Reading files, listing directories, searching the project, and compile-only Lua syntax checks do not require confirmation. Auto-approve applies only to file operations inside the current project. “Auto-run sandbox code” is on by default; when disabled, every Lua sandbox run requires confirmation.

“Auto-approve network requests” is on by default. Sandbox code with network_hosts runs directly only when both “Auto-run sandbox code” and “Auto-approve network requests” are enabled. Disabling network auto-approval makes out-of-sandbox fetches, sandbox network access, and MCP tool calls display confirmation dialogs. This setting does not affect model API requests, connection tests started by the user, or MCP tool-list refreshes.

Running Lua Code

The assistant can compile code with the built-in LuaJ++ parser to check syntax without executing it or requiring confirmation. Runtime validation uses a restricted sandbox instead of the current project's normal Lua environment. The sandbox can validate pure Lua algorithms and explicitly approved public HTTPS APIs, but cannot access activity, Java/Android APIs, files, private networks, require, or luajava. See AI Lua Sandbox for available libraries, network authorization, output handling, and timeout limits.

Fetching Network Content

The assistant can read public HTTPS pages, documentation, and textual APIs; per-call confirmation is controlled by “Auto-approve network requests.” This tool only supports GET / HEAD. It accepts no custom request headers, separate credentials, cookies, request body, or self-signed certificate, and it never saves a response to a file automatically. Query parameters already present in the URL are sent as written and are shown in the dialog when auto-approval is disabled.

Network reads reject IP literals, localhost, private networks, non-443 ports, and non-HTTPS URLs. Every DNS result must be public. Up to three redirects are allowed, and each target is fully revalidated. Response bodies are limited to text, JSON, XML, or JavaScript and are subject to timeout and size limits. Web content is untrusted data and cannot override user requests or built-in safety rules.

Command Menu

The command button beside the input field provides:

  • Compress context: summarize older conversation messages while keeping recent messages.
  • Undo / redo conversation turn: change chat history without executing tools again.
  • Undo / redo file change: restore the latest Agent file transaction.
  • Switch conversation: conversations are isolated by project.
  • Settings: change sampling temperature, retries, safety options, additional instructions, and MCP servers. Additional instructions do not replace built-in safety or tool rules.

File undo checks the file fingerprint and refuses to overwrite externally modified content.

The context window and maximum output belong to each model configuration. Switching models switches both limits; values from the previous global settings are migrated to existing models.

MCP

Add HTTP-based MCP servers in Settings. The assistant prefers current stateless Streamable HTTP and supports older session-based Streamable HTTP and legacy HTTP+SSE. It does not support stdio servers or launch local commands.

  • The server URL must be reachable over HTTP or HTTPS.
  • MCP tools operate on external systems and require per-call confirmation when “Auto-approve network requests” is disabled.
  • Do not connect untrusted servers or expose API keys in server settings.
  • If a server is unavailable, disable or remove it and refresh the tool list.

Local Skills

A Skill is a local Markdown guide for a specific task. The assistant only reads SKILL.md; it does not execute Lua code from a Skill or download Skills.

Global Skills:

/sdcard/LuaJ/agents/skills/<skill-name>/SKILL.md

Project Skills:

<project>/.agents/skills/<skill-name>/SKILL.md
<project>/skills/<skill-name>/SKILL.md

A Skill may use simple frontmatter:

---
name: lua-review
description: Check Lua style and common mistakes
triggers: lua, review, check
---

Write the Skill rules and review steps here.

When a message is sent, the assistant matches Skill names, descriptions, and keywords, then adds the selected Skill body to the request. Never put secrets, private data, or unconditional dangerous actions in a Skill.

Folder Structure

Agent data is stored in /sdcard/LuaJ/agents, separately from project source files:

/sdcard/LuaJ/
├── Projects/                         Project roots (example)
│   └── MyProject/
│       ├── .agents/
│       │   └── skills/               Skills for this project
│       │       └── review/
│       │           └── SKILL.md
│       ├── skills/                   Alternative project Skill directory
│       │   └── release/
│       │       └── SKILL.md
│       ├── init.lua                  Project entry point
│       └── ...                       Project source and resources
├── agents/                           External Agent runtime data
│   ├── skills/                       Global Skills
│   │   └── lua-review/
│   │       └── SKILL.md
│   └── projects/
│       └── <project-hash>/          Data isolated per project
│           └── changesets.json       File undo/redo history
└── ...

Put project-specific rules in the project directory and shared rules in /sdcard/LuaJ/agents/skills. Use different Skill names across directories.

Data and Safety

Conversation history is stored in app data. Project-scoped Agent data is stored at:

/sdcard/LuaJ/agents/projects/<project-hash>/

File history uses changesets.json and keeps a limited number of recent records. Each project has a separate directory and file undo history. API keys are not written to the Agent project data directory.

Troubleshooting

No response after sending

Check the API key, API URL, model name, Chat Completions / Responses selection, and network connection. You can use the connection test in model settings. The coding Agent requires structured tool calling from both the model and provider; unsupported models may return an API error or provide text only.

Context compression did not change anything

Compression needs at least two separable groups of history. With very little conversation there is no older content to summarize.

File undo failed

If a file was edited after the Agent changed it, fingerprint validation prevents an overwrite. Review the current file and resolve the conflict manually.

Permission errors

The Agent needs access to the current project and its data directory. Grant NeLuaJ+ file-management permission and make sure the project path is readable and writable.
