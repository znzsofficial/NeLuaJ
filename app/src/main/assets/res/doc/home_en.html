Home and project management

Home has four destinations: Projects, Chats, Help and Settings. Opening a project enters a separate editor workspace. Compact windows use bottom navigation; wider windows use a rail with the same destinations.

Create or continue a project

  1. Choose Create Project, select a template, then enter the app name, package name and theme. Review the generated file list and permissions before creating it.
  2. With Open after creation enabled, the editor opens the new project's main.lua. Otherwise, you stay on Home.
  3. Opening an existing project attempts to restore its tabs, active file and cursor instead of always opening main.lua.

Recently opened uses actual open history, not directory modification time. Search matches app names, folder names and package names; clearing it restores the full list.

Choose a template

Six starting points are included: blank page, interactive form, local checklist, multiple pages, settings and a local WebView. Blank supports legacy themes; the other templates target Material 3 and dynamic colors. Incompatible theme combinations cannot be generated.

Debugging, network permission and optional utility modules are advanced settings. Templates do not request network access by default. Every generated project includes a README describing its entry points, example behavior and packaging. Files remain editable, and template updates do not overwrite existing projects.

On failure, your inputs remain available and an error explains the problem. Existing project folders are never overwritten. After an interrupted creation, inspect the reported target or staging directory before deciding whether to keep, move or delete your leftover files.

Open an existing folder

Open project folder accepts the full path of a readable folder and opens it directly. It does not copy or overwrite projects and is not a ZIP importer. Extract downloaded archives to an accessible directory first.

Successful creation does not guarantee the subsequent navigation succeeded. If opening fails, check the destination, files and file access before creating another project with the same name.

Permissions, empty lists and read failures

  • Use Grant file access to open system authorization. Returning after granting access in Settings allows the app to refresh.
  • For a read failure or invalid project-root folder, check the location and retry. Previously loaded results may remain visible; that does not mean the latest read succeeded.
  • No projects means a successful read found none. No matching projects only describes the current search.

Start an AI conversation

Choose New conversation on Chats, select a project, and enter its editor AI panel. Create a project first if none is available. See the built-in AI Agent guide for model setup.

The Home list reads conversation metadata; opening a conversation loads its messages. A deleted project or missing conversation is not silently replaced by another project. Failed navigation can be retried or dismissed; retained requests can also be retried from the editor's More menu.

Leave safely after a save failure

Back closes the file drawer or search first, then checks saving. A failure keeps edits in the current buffer and offers Retry or Cancel. Discard requires a second confirmation. Menu exit uses the same guard.

There is no automatic unsaved-draft recovery guarantee. Workspace state stores paths, tabs and cursors, not unsaved text. Pre-overwrite backups are not copies of the current buffer. See backups and crash logs (Chinese). Save successfully before the process can be reclaimed.

Rename and recover a project

  • Close related editors first so tabs and autosave cannot keep writing old paths. The conservative occupancy check may also block renaming while another editor remains alive.
  • Renaming reassociates workspace, conversations, recent history and root Agent storage, then moves the directory last. Journals and source snapshots are retained on failure; this is not a transaction across all files.
  • If Home reports an incomplete rename, close editors and explicitly retry. Recovery may briefly pause the app. Do not manually delete source data, journals or backups.
  • Absolute paths in old file-change undo history are not rewritten, so replay after renaming is not guaranteed. Occupancy detection is not a complete multi-window or cross-process lock.

Settings and window changes

The editor's tablet preference temporarily falls back to a drawer in compact split-screen windows, then restores columns when widened without changing the preference. Theme changes recreate pages. Tab, search and list restoration mechanisms exist, but process-death and window behavior still need device-specific verification.
